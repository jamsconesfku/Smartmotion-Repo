# SmartMotion Flight: the native Windows version

The same game as the browser version (`docs/games/smartmotion-flight.md`), rebuilt in the **Godot 4.6** engine so it runs as a normal Windows program on the PC's graphics card. Source: `godot/`. Since v1.5.0 the world is the **real Duxford area** built from free open data (see "Real world" below); aircraft, signs and sky are still made in code, and the only other outside files are the Barlow fonts (SIL Open Font Licence) and CC0 textures from ambientCG.

## Getting it
- Built automatically by GitHub Actions (`.github/workflows/build-native.yml`) whenever `godot/` changes on `main`, and published as the **native-latest** release: https://github.com/jamsconesfku/Smartmotion-Repo/releases/tag/native-latest (the repo is private, so sign in to GitHub first). Download `SmartMotionFlight-Windows.zip`, unzip, run `SmartMotionFlight.exe`. The zip's `README.txt` has the steps.
- Windows shows a "Windows protected your PC" screen because the program isn't code-signed: More info > Run anyway.
- Build locally: `GODOT=/path/to/Godot_v4.6.1 scripts/build-native.sh` (needs the matching export templates).

## What's better than the browser version
Forward+ renderer (Vulkan): real-time soft sun shadows across the whole scene, ambient occlusion, bloom, filmic tone mapping, 4x anti-aliasing, a much sharper 4096-pixel painted ground map, GPU-displaced terrain, instanced houses and trees with distance culling, Barlow brand fonts, and a fallback "compatibility" mode (`Play (compatibility mode).bat`) for older graphics cards.
The flight model is the same physics ported line for line (`godot/scripts/flight_model.gd`), checked by `godot/tests/test_flight.gd` (takeoff, climb, level flight, turns, stalls, landing, stopping), which also runs in the build.

## VR (Meta Quest 3)
OpenXR through **Meta Quest Link** (cable) or Air Link: in the Quest Link app set it as the active OpenXR runtime, start Link, then press "Fly in VR" (or `Play (VR - Meta Quest).bat`). Controls: right stick pitch/roll, right trigger/grip more/less power, left stick power/rudder, left trigger brakes, A flaps, B recentre, X pause, Y restart. The keyboard works in VR too (WASD to fly, Shift/Ctrl power); the game brings its window to the front when VR starts and shows a message if the keyboard isn't reaching it. The desktop window mirrors the view and shows the pause menu. First tested on Sam's Quest 3 on 9 Nov 2026: VR works, but flying was hard to control, which led to the v1.4.0 control changes. Still to tune: seat position, comfort and frame rate.

## The aircraft: Skysmart's Bulldog (v1.6.0)
You now fly **Skysmart's own Scottish Aviation Bulldog**: G-SMAT, ex-RAF XX658 (built 1974, Cambridge University Air Squadron, code 07; Skysmart's since October 2019, flown from Duxford). It replaces the made-up light trainer; the WW2 fighter stays as the second choice. Built in code in `godot/scripts/bulldog.gd`:
- **Shape from the real dimensions**: span 10.06 m, length 7.09 m, height 2.28 m, wing area 12.02 m², tapered wing (1.45 m root to 0.95 m tip chord) with a proper aerofoil and 6° dihedral, boxy side-by-side fuselage, sliding bubble canopy with frames, swept fin, fixed tricycle gear, two-blade 1.88 m Hartzell propeller (black, yellow tips). Ailerons, elevator, rudder and flaps move.
- **Flight model** (`bulldog` in `flight_model.gd` and `flightmodel.js`): 1,000 kg, 200 hp Lycoming IO-360, clean stall about 55 kt, top speed about 130 kt, crisp aerobatic roll. Passes all physics checks.
- **Livery**: RAF light-trainer style (white upper, light grey under, signal-red bands and tips, black anti-glare panel, type D roundels, fin flash, serial XX658, code 07). **Assumption**: we found no clear photo of G-SMAT's current paint; send photos and we'll match it exactly.
- **Cockpit, built for VR**: a 3D panel at real scale with live round gauges (airspeed with the Bulldog's arcs, attitude, altimeter, turn coordinator, heading, vertical speed, g-meter with max/min, RPM, manifold pressure, oil, fuel, CHT, amps, clock), each behind its own bezel and glass so they have depth in the headset; radios, switches, magneto key, annunciators and placards; glare shield and compass; two control sticks that move with your inputs, rudder pedals, throttle/propeller/mixture levers, trim wheel, flap lever and fuel selector; bucket seats, side lining, canopy frames and the propeller arc in front. An instructor sits in the right-hand seat and looks around. The panel is drawn at 1,800 pixels per metre and updates every frame so the needles move smoothly in VR.

## Real world (v1.5.0)
A 32.8 km square centred on the middle of Duxford's hard runway (real heading 058 true, 1,448 m), made by `scripts/build_world_data.py` into `godot/assets/world/` (re-run it to refresh; needs `pip install rasterio pyproj numpy pillow duckdb shapely requests`, about 5 minutes):
- **Ground heights**: Copernicus DEM GLO-30 (`height.bin`, 1024 x 1024, 32 m), smoothed (it is a surface model, so woods and roofs are bumps), the airfield flattened at 33.5 m, the edges faded so the map can repeat.
- **Ground photo**: Copernicus Sentinel-2, 7 July 2023, six passes stitched (`ortho.jpg`, 4096 px, about 8 m a pixel), colour-corrected for a game. Pick another day with `S2_DAY=YYYY-MM-DD`.
- **Land cover**: ESA WorldCover 2021 (`landcover.png`: red trees, green built-up, blue water, alpha grassland). Drives the close-up textures, the shiny river and where trees grow.
- **Buildings**: 129,117 real footprints and heights from Overture Maps (OpenStreetMap and others) (`buildings.bin`), including the real Duxford hangars (the made-up hangars are gone). Houses get pitched roofs; walls are brick, render or metal cladding with windows; roofs take their colour from the satellite photo. Crash checks use the real buildings near the aircraft.
- **Trees**: one tree per 8 m woodland pixel, streamed in 1 km squares: a detailed tree up to 1.3 km, a simple one to 4 km, the photo beyond.
- **Close-up ground**: ambientCG CC0 grass, soil, tarmac and concrete photo textures with normal maps, mixed into the satellite colour within about 2 km so the ground has grain and bumps when low.
- Beyond the real square the old painted countryside carries on to the horizon.
- Licences and the credits we must show: `data/licences.json` LIC-10 to LIC-14; the credits are on the game's Controls screen and in the download's README.

## 3D clouds (v1.5.0)
`shaders/clouds_volumetric.gdshader`: a full-screen raymarch through a cloud layer 950 to 2,300 m up, shaped by a weather map and 3D noise (made in code by Godot's noise generator), lit with sun absorption, dark bases and silver edges towards the sun. Clouds drift with the wind and cast moving shadows on the ground. The scene's depth hides clouds behind hills and buildings. Used on Medium/High with the Forward+ renderer; VR, Low and compatibility mode use the lighter cloud cards.

## Performance (RTX 4060 target)
High: about 1 M triangles of nearby trees, about 2 M of far trees, 16,000 buildings within 7 km, 72 cloud steps a pixel. If it drops below 60 fps, use Medium (fewer trees, shorter range, 44 cloud steps). In VR the 3D clouds, SSAO and SSIL are switched off. Load with `--stats` (after `--`) to log triangles, draw calls and fps every two seconds in the diagnostics log.

## Graphics overhaul (v1.14.0)
Sam, 11 Nov 2026: "massively improve the graphics in every way possible, with good settings, ultra realistic Microsoft Flight Simulator level". The game can't match MSFS's worldwide photo scenery and photogrammetry cities from free data, but the lighting, sky and weather now work the way MSFS's do. Checked only on the build machine (software graphics, no GPU): frame rates on the RTX 4060 still need Sam's check.
- **Physical sky** (`shaders/sky.gdshader`, `scripts/atmosphere.gd`): the sky is worked out from how sunlight scatters in the air (Rayleigh, Mie haze, ozone), followed from the camera out to space, at quarter resolution with the sun disc and high cloud added at full resolution. The same model on the CPU gives the sunlight colour and strength and the haze colour, so the ground, the fog, the clouds and the sky always agree. The sky's reflections update a little at a time (incremental), only when the sun, the weather or the camera height (150 m steps) changes.
- **Times of day**: Morning, Midday, Golden hour, Sunset (`World.TOD`, keys `morning`, `day`, `golden`, `sunset`). The sun's colour comes from the air it passes through; a low sun opens the "camera" up a little (as the eye does) so sunset isn't murky.
- **Weather** (menu, live; `World.WEATHER`, setting `weather`): Clear, Few clouds, Scattered (the old look, default), Broken, Overcast. Each sets cloud cover, cloud base and top, haze, fog, high cloud, sunlight strength and cloud shadows; Overcast adds a grey deck to the sky and soft, dim sunlight.
- **Cloud shadows on everything**: the clouds' map is read on the CPU each frame along the sun; when the aircraft is under a cloud the sunlight dims (smoothly), so the aircraft, cockpit, buildings and trees go into the shadow with the ground.
- **3D clouds**: light scattered several times inside the cloud (three "octaves"), sky light from above and ground light from below, darker deep inside; on Ultra a finer shape map (96³) and a sharper cloud map.
- **3D grass** (`shaders/grass.gdshader`, `World._grass`, setting `grass`): clumps of blades round the camera when you are within about 50 m of the ground, in Flight only (they would poke through the racing track and the coaster station). Every clump is placed in the shader from its number (no CPU work per frame), on the real ground, coloured from the satellite photo, only where the ground is grass (not the runway, tarmac, roads, water, bare fields or under buildings), swaying in gusts. Best: 36 m round you; Ultra: 46 m, denser; Balanced: 28 m; VR smaller.
- **Ground**: the slope is worked out per pixel from the height data, so hills, valleys and ridges are shaded properly all the way to the horizon (the far rings used to light whole hillsides flat); the river has finer ripples up close.
- **Picture**: AgX tone mapping (film-like, keeps colour in bright skies and sunlit paint), softer wider bloom, stronger aerial perspective (distant land takes the colour of the sky behind it), debanding (no steps in the sky), 16x texture filtering on Best and Ultra (sharp ground at low angles), finer SSAO/SSIL and 512 sky reflections on Ultra.
- **New settings**: Smooth edges and resolution (`aa`: TAA, SMAA, FSR 2 Native, FSR 2 Quality 67%, FSR 2 Fast 50%; live; not used in VR, which keeps 2x MSAA), 3D grass On/Off, Brightness (Darker/Normal/Brighter), V-Sync On/Off, Show frames per second (green 55+, amber 40+, red). Test options `--aa=`, `--weather=`, `--brightness=`, `--grass=off`, `--tod=morning|sunset`, `--shot_frames=N` (frames to wait before a screenshot, default 30).
- **Not done**: higher-resolution aerial photos near the airfield. The Environment Agency's 25 cm aerial photos of England would be the biggest step for low flying, but they come as large manual downloads and we couldn't confirm the licence; check the licence before using them.

Settings > Motion rig > On sends the same JSON frame as the browser version (see `docs/games/smartmotion-flight.md` for the fields) over **UDP** (default `127.0.0.1:4123`, 60 per second), straight from the game, so no bridge program is needed. Our own **SmartMotion Motion** (`motion/`, `SmartMotionMotion.exe` in the same download, v1.9.0) listens on that port and drives the Motion4Sim controller, replacing FlyPT Mover: see `docs/games/smartmotion-motion.md`. In VR the game also reads the seat position it sends back (port 4124) and cancels the rig's movement out of the headset view (`scripts/motion_comp.gd`).

## FlyPT Mover link (v1.11.0)
Settings > FlyPT Mover (on by default) makes the game look like **X-Plane 11** on the network, so FlyPT Mover's built-in "X-Plane 11 (UDP)" source reads it with no plug-in (`scripts/xplane_link.gd`, owned by `telemetry.gd`). It works for every game, built from the same telemetry frame as the rig link.
- Sends X-Plane 11's **BECN** beacon (multicast 239.255.1.1:49707, once a second, "X-Plane 11.55, master, port 49000"): Mover's X-Plane source waits for this before it asks for data (1.11.3; Sam's Mover showed "Request to port 49000" but never asked until then).
- Listens on **UDP *:49000** (all addresses, since 1.11.3: Mover sends to the PC's network address; Windows asks once about the firewall) and answers X-Plane requests: **RREF** (named datarefs at the asked rate, replies `RREF,` + index/float pairs), **DSEL/USEL** (DATA rows sent back to the asker) and **RPOS** (`RPOS4` position packets). Unknown datarefs are answered with 0 and written to the log (`SmartMotionFlight-log.txt`), so we can see what Mover asks for.
- Mover sends its requests only once, when its source connects. Since 1.11.4 the game saves them to `user://flypt_mover.json` and carries on sending after a restart (the VR restart included); a new request from the same address replaces the old one.
- Racing (1.11.6): below 8 m/s the felt sideways force blends from the tyre model to speed x yaw rate (the tyre forces gave 1.6 g at walking pace while steering); this changes the rig frame too. Real car forces: about 1 g accelerating, 2.4 g braking, up to 1.8 g cornering.
- Racing (1.11.5): sends `rpm` (0-12,000) and a shake in the vertical force on kerbs (0.12 g), gravel (0.08 g) and grass (0.05 g), scaled with speed, in the X-Plane values only (SmartMotion Motion makes its own rumble). Racing reports on the ground, so Mover uses its GROUND pose; Space and the Coaster ride use AIR. The log lists every dataref Mover reads ("FlyPT Mover is reading: ...").
- Also sends X-Plane **DATA** rows 1, 3, 4, 13, 14, 16, 17, 18, 20, 21, 25, 37 to 127.0.0.1:49001, 30 a second (settings `flypt_port`, `flypt_out`).
- Values: attitude `theta/phi/psi`, rates `P/Q/R` (deg/s) and `Prad/Qrad/Rrad`, world-frame `local_vx/vy/vz` and accelerations `local_ax/ay/az` (m/s², gravity removed; X-Plane axes x east, y up, z south = the game's world axes), `g_nrml/g_axil/g_side` (g_axil taken along the aft axis, so it is negative when speeding up; not checked against real X-Plane), speeds, heights, lat/lon, throttle, rpm, flaps, on ground, paused. When the game is paused or in the menu it sends "still" (1 g up, no rates).
- The orientation is rebuilt from pitch/roll/heading (`XPlaneLink.basis_from`). Checks: `godot --headless --path godot --script res://tests/test_xplane.gd` (acts as Mover over UDP).
- Not tested yet against Mover itself: we couldn't confirm which requests Mover's X-Plane source sends (its documentation site wasn't reachable from the build session). The link covers all three X-Plane ways, and the log shows what Mover asked for.

## Layout of `godot/`
`scripts/`: `main.gd` (controller, input, cameras, VR), `flight_model.gd`, `terrain.gd`, `world.gd` (sky, ground, Duxford, signs, scenery), `aircraft_model.gd` + `instruments.gd` (aircraft and cockpit), `ui.gd` (menus, HUD), `telemetry.gd`, `motion_comp.gd` (VR motion compensation), `synth.gd` (sound), `settings.gd`. `shaders/`: ground painting, ground, sky. `assets/`: logos, fonts. `package/`: files added to the download. `tests/`: physics checks.

Test options (after `--` on the command line): `--auto` (skip the menu), `--aircraft=fighter`, `--mode=gates`, `--start=air`, `--tod=golden`, `--cam=cockpit`, `--q=low|medium|high`, `--vr`, `--telemetry=host:port`, `--shot=file.png --shot_after=6` (save a screenshot and quit).
